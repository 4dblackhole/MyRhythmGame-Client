# 코드 품질 재검토 반영

레거시 제거 후 검토에서 재현한 네 오류를 수정했습니다. 기존 Scene/모드/문서의
책임 경계를 유지하며, 전체 코드의 일괄 서식 변경이나 새 게임모드는 추가하지 않았습니다.

## 수정된 경계

- `Automation/EffectValidation`은 효과 값과 구간 보간, 히트사운드 변경 및 타임라인
  위치의 공통 검증을 소유합니다. EffectParser는 문법/원본 행 진단을 유지하고,
  ChartEditor와 TaikoMode의 직접 DTO 세션 생성도 같은 검증을 거칩니다.
  편집된 이름 있는 식은 세션 생성 전에 다시 컴파일하므로 오래된 공유 식을 사용하지 않습니다.
  음수 볼륨, 비유한 값, 지원하지 않는 볼륨 대상, 마디 밖 위치, 음수/clock 범위 밖
  duration을 공통 경로에서 거부합니다. YME 문법은 변경하지 않았습니다.
- `PlaySession`은 종류/대상별 트랙의 마지막 정상값을 소유합니다. 사용자 식의
  샘플 사이 특이점과 잘못된 값은 해당 트랙만 보류하며 정상 평가가 다시 나오면 갱신합니다.
  첫 평가 실패에는 검증된 From을 초기값으로 사용합니다. Reset/SetEffects가 값과 오류를
  함께 초기화합니다. 정상 경로에서는 식 재파싱이나 트랙 탐색용 새 map 할당이 없습니다.
  Controller는 오류를 전달하고 Presenter는 기존 오류 HUD를 사용해 표시/숨김만 담당합니다.
- `ChartEditor`의 실제 컴파일 배율 인덱스는 `(배율, 안정 노트 ID)`의 균형 트리입니다.
  추가/삭제는 해당 노드만 갱신하고, BPM/효과 수정은 후보 인덱스 준비 후 다른 캐시와
  함께 교체합니다. 실패 시 기존 문서와 인덱스는 보존합니다.
  TaikoEditorScore는 사용자 식에 대해 끝값으로 그리드를 제외하지 않고, 기존 제한 범위에서
  실제 X좌표로 검사합니다. 느린 노트 조회와 노트가 없는 그리드 스냅을 별도로 검증합니다.
- 엔진 Run은 숨김 config를 runtime 생성 전에 읽고, fatal error를 항상 디버그 출력에
  기록하되 숨김 실행에는 모달 대화상자를 띄우지 않습니다. 기존 Client Shutdown과
  renderer/audio 정리 순서는 보존했습니다. 기존 SDK 테스트에 선택형 오류 주입 route만
  추가했으며 별도 엔진 검증 프로젝트는 만들지 않았습니다.
- `EditorAnalysisController`는 취소 권한을 가진 고유 소유자이므로 복사/이동을 명시적으로
  금지했습니다. 공유 job의 결과 수명이나 worker 취소 방식은 변경하지 않았습니다.

## 회귀 검사

`YmeEffectsTests`에 독립 테스트 세 개를 추가했습니다. 129개 로드 샘플은 통과하지만
실제 시각에서는 실패하는 나눗셈/음수 볼륨, 다른 트랙과 다음 명령의 독립성,
정상값 복구/초기 실패/Reset/SetEffects, 편집/플레이 검증 일치와 식 재컴파일을 검사합니다.
`Dip: 1-3*u*(1-u)`의 끝값은 1이지만 실제 노트의 배율은 0.25인 사례로 표시 조회와
추가/삭제/복사/BPM/효과 변경의 인덱스 갱신을 확인합니다.

Presentation의 EditorModeTests는 실제 Taiko 그리기/삭제/스냅을, GameplayJudgementTests는
공통 오류 HUD의 표시/숨김을 검사합니다. 엔진 SDK의 `--headless-error`는 실제 D3D12와
FMOD NoSound 실행에서 Update 예외를 주입하고 실패 반환과 Shutdown 호출을 검사합니다.
실행기에는 30초 timeout을 두어 모달 회귀가 자동 실행을 무한히 멈추지 않게 했습니다.

최종 빌드·정적 분석·실행 결과와 수동 확인 여부는 [Verification](../Verification.md)에 기록합니다.
